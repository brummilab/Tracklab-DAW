# Handtests Meilenstein M1: Audio-Geräte (Prüfaufgabe V1)

Die Gate-Tests laufen ohne Hardware (Fake-Gerätetyp und Hosted Device, `tests/io/`). Die echten Treiber kann nur ein
Mensch mit echter Hardware prüfen. Diese Datei beschreibt die Schritte; das Ergebnis trägt David in
`team/TODO-PO.md` (Prüfaufgabe V1) ein.

> **Stand: Gerüst** (Karte M1-06, Test-Writer). Der Implementer ergänzt die genauen Aufrufe, sobald das Programm
> sie bietet. Bis `tracklab-cli` (Karte M1-07) da ist, gilt als Aufrufweg das Hilfsprogramm, das der Implementer
> in M1-06 angibt `[offen]`. Die Befehle heißen `io.list_device_types`, `io.list_devices`, `io.get_device`,
> `io.set_device` (Schemas: `docs/commands.md`).

## Vor dem Test (alle Systeme)

1. Aktuellen Stand holen und bauen (Anleitung: `README.md`).
2. Für den Test einen eigenen Einstellungsordner nehmen, damit die normalen Einstellungen unberührt bleiben
   `[offen: Umgebungsvariable oder Option, vom Implementer festzulegen]`.
3. Kopfhörer oder Lautsprecher **leise** drehen, bevor ein Gerät geöffnet wird.
4. Notieren: Betriebssystem, Version, Audio-Interface (Hersteller, Modell, Anschluss), Treiberversion.

Für jeden Abschnitt gilt dieselbe Abfolge:

1. Typen listen (`io.list_device_types`): der Typ erscheint, ohne Hinweis oder mit dem erwarteten Hinweis.
2. Geräte listen (`io.list_devices`): Ein- und Ausgabegeräte, Kanalnamen, Abtastraten, Puffergrößen stimmen mit dem
   Interface überein.
3. Gerät setzen (`io.set_device`): Typ, Eingabe- und Ausgabegerät, 48000 Hz, Puffer 256, Kanäle 0 und 1.
4. `io.get_device`: zeigt genau diese Werte, `open` ist `true`.
5. Ton: Testton oder Wiedergabe eines Projekts kommt am richtigen Ausgang an (kein Knacken, kein Aussetzen über
   eine Minute).
6. Eingang: Signal am Interface einspeisen, Pegel am richtigen Kanal sichtbar (ab der Mixer-/Aufnahmekarte; bis dahin
   nur Schritt 1 bis 5).
7. Neustart: Programm beenden, neu starten, `io.get_device`: dieselben Werte, Gerät wieder geöffnet, ohne dass etwas
   gewählt wurde.
8. Fehlerfälle: Samplerate, die das Gerät nicht kann (z. B. 22050), und ein Gerätename, den es nicht gibt:
   `io.set_device` meldet einen Fehler und das laufende Gerät bleibt unverändert.
9. Gerät abziehen (USB-Interface ausstecken), Programm neu starten: kein Absturz, `io.get_device` zeigt ein anderes
   Gerät oder `open: false`; danach Gerät wieder anstecken und erneut wählen.

Ergebnis je Abschnitt: **bestanden / nicht bestanden / nicht prüfbar** mit Datum und einer Zeile Bemerkung.

## ALSA (Linux Mint / Ubuntu)

Voraussetzung: Mint 22.x oder Ubuntu 24.04, Desktop mit PipeWire (Standard).

```bash
# Ohne sudo: was läuft?
pactl info | grep "Server Name"
aplay -l
id
```

- PipeWire hält die Karte; ein direktes `hw:`-Gerät kann „busy“ melden. Das ist erwartet. Gewählt wird dann ein Gerät
  über PipeWires ALSA-Plugin (`default`, `pipewire`) oder die Karte wird zuvor freigegeben
  `[VERIFIZIEREN: Verhalten auf Mint 22 mit PipeWire 1.0.5]`.
- ALSA ist die **Zweitoption** (Design E36). Die Abfolge oben mit Typ `ALSA`.
- Erwartung: Puffergröße und Samplerate kommen von Tracklab (anders als bei JACK).
- Hinweis: JUCE setzt für den ALSA-Thread unter Linux keine Echtzeit-Priorität. Aussetzer bei kleinen Puffern (64)
  sind möglich und kein Fehler dieser Karte; Beobachtung notieren.

## JACK über PipeWire (Linux, Standard)

Voraussetzung: `pipewire-jack` installiert (Laufzeit-Pakete laut `team/research/audio-backends-linux/NOTIZEN.md` §5).

```bash
# Paketstand prüfen (ohne sudo)
dpkg -l pipewire pipewire-jack wireplumber rtkit libjack-jackd2-0
```

```bash
# sudo (macht David, R9): nur falls Pakete fehlen
sudo apt install pipewire pipewire-audio pipewire-jack wireplumber rtkit
```

1. **Ohne** `pw-jack` starten: `io.list_device_types` zeigt den Typ `JACK` ohne Geräte und im Feld `hints` den
   Hinweis, Tracklab mit `pw-jack` zu starten.
2. Mit `pw-jack` starten:

   ```bash
   pw-jack ./build/linux-gcc-release/<Programm>   # [offen: Pfad und Name des Programms]
   ```

   Erwartung: `JACK` hat Geräte, `hints` ist leer.
3. Abfolge oben mit Typ `JACK`. Puffergröße und Samplerate bestimmt **PipeWire**, nicht Tracklab: Wert mit
   `pw-metadata -n settings 0 clock.force-quantum 256` setzen und prüfen, dass `io.get_device` ihn zeigt
   `[VERIFIZIEREN]`.
4. 12 und mehr Eingänge: im Pro-Audio-Profil des Interfaces erscheinen alle Kanäle einzeln
   (`pactl list cards short`, Profil `pro-audio`) `[VERIFIZIEREN]`.
5. Latenz grob: Loopback-Kabel Ausgang 1 nach Eingang 1, Wert notieren (die genaue Messung kommt mit
   `io.measure_latency`, späterer Meilenstein).

## WASAPI (Windows 10/11)

Voraussetzung: Windows 10 oder 11, Standard-Audiogerät oder USB-Interface.

1. Typen listen: drei Typen für WASAPI (geteilt, exklusiv, niedrige Latenz); die genauen Namen notieren
   `[VERIFIZIEREN]`.
2. **Geteilt:** Abfolge oben; Samplerate ist die Systemformat-Samplerate (Windows-Klangeinstellungen). Eine
   abweichende Rate wird abgelehnt.
3. **Exklusiv:** Abfolge oben. Andere Programme (Browser, Mediaplayer) schweigen währenddessen oder melden den
   Zugriff; nach Beenden von Tracklab sind sie wieder da.
4. **Niedrige Latenz:** Abfolge oben mit kleinstem angebotenem Puffer; Aussetzer notieren.
5. Windows-Klangeinstellungen: Gerät dort als Standard setzen und prüfen, dass Tracklab die Wahl nicht ändert.

## ASIO (Windows 10/11)

Voraussetzung: ASIO-Treiber des Interface-Herstellers installiert (z. B. Herstellertreiber; ASIO4ALL ist kein
Ersatz für den Test eines echten Interfaces). Der Tracklab-Build enthält ASIO (`JUCE_ASIO=1`, Lizenz: GPLv3-Option des
SDK, siehe `THIRD_PARTY_NOTICES.md`).

1. Typ `ASIO` erscheint in `io.list_device_types`. Fehlt er: Build ohne `JUCE_ASIO=1` (Fehler dieser Karte melden).
2. Geräte listen: ein Gerät je ASIO-Treiber, Ein- und Ausgänge getrennt aufgeführt wie beim Treiber (ASIO ist ein
   gemeinsames Gerät für beide Richtungen); Kanalnamen wie im Treiber-Bedienfeld.
3. Abfolge oben. Puffergrößen kommen aus dem Treiber; kleinste und größte Größe je einmal setzen.
4. 12 oder mehr Eingänge (falls das Interface sie hat): Kanäle 0 bis 11 aktiv setzen, `io.get_device` zeigt alle zwölf.
5. Treiber-Bedienfeld: wenn das Interface eines hat, öffnet sich keine Dialog-Blockade (Tracklab reagiert weiter).
6. Anderes Programm mit demselben ASIO-Treiber starten: `io.set_device` meldet einen klaren Fehler, kein Absturz.
