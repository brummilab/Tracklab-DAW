# M0-07: Gate auf C++/CMake umbauen (Entwurf)

Meilenstein: M0 · Design: Rev 1, Abschnitt 8 · Agent: implementer

> Entwurf, abhängig von M0-06 und ADR-001. Vorschlag aus M0-04 (`team/research/ci-packaging/NOTIZEN.md`).

## Fakten
- Auftrag §3.3/§11: CMake Release + Debug (`-Werror` für `src/`), `ctest`, clang-format/clang-tidy, RTSan-Job
  (Linux/Clang), Golden/LUFS sobald vorhanden. `gate.sh` und `gate.ps1` gleichwertig; CI ruft dieselben Skripte auf.
- Das Gate schreibt nur nach `${GATE_BUILD_DIR:-${TMPDIR:-/tmp}/tracklab-gate}` oder `build/` (ignoriert).
- Runner gepinnt: `ubuntu-24.04`, `windows-2025` (nicht `windows-latest`).
- RTSan ab Clang 20.1 (`-fsanitize=realtime`, `-Wfunction-effects`), nur Linux; Clang ≥ 20 über `ubuntu-26.04` oder
  Paket `clang-20` auf 24.04.
- Caching: ccache (Linux), sccache (Windows, `CMAKE_MSVC_DEBUG_INFORMATION_FORMAT=Embedded`), Debug/Release getrennt.
- Die Statik-Schritte (Pflichtdateien, Secrets, Audio) bleiben; der Platzhalter für den Build in `scripts/gate.sh` wird ersetzt.

## Struktur
- `CMakePresets.json`: `linux-gcc-{debug,release}`, `linux-clang-{debug,release}`, `linux-clang-rtsan`,
  `windows-msvc-{debug,release}`.
- `gate.sh static|build|rtsan|tidy|all` (Default `all`); `gate.ps1 static|build|all` (MSVC).
- `gate.yml`: `static` → `build-test-linux` (GCC 14, Clang 18), `rtsan-linux`, `build-test-windows`; `concurrency` je Ref;
  Testberichte als Artefakt bei Fehlschlag. Packaging/Release folgen in eigenen Karten.
- Umstellung in Schritten mit je einem Commit: static + GCC → MSVC → Clang/RTSan.

## Eigene Dateien
`scripts/gate.sh`, `scripts/gate.ps1`, `.github/workflows/gate.yml`, `CMakePresets.json`, `.clang-format`, `.clang-tidy`
