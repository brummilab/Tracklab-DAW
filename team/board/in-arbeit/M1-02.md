# M1-02: Command-Registry v1 mit Schema-Validierung und Export

Meilenstein: M1 · Design: Rev 3, §3 „Registry v1“, §4 (Tool-Namen) · Agent: test-writer → implementer · Abhängig: M1-01

## Fakten
- DESIGN Rev 3 §3 und `team/research/m1-fundament/NOTIZEN.md` §4. Abhängigkeiten als Submodule mit festem Tag:
  nlohmann/json `v3.12.0`, pboettch/json-schema-validator `2.4.0` (beide MIT) unter `third_party/`.
- `core::Command` (id, titleDe, descriptionEn, paramsSchema, resultSchema, flags `readOnly|undoable|destructive|longRunning`,
  shortcut, menuPath, handler), `core::CommandRegistry` (registrieren, auflisten, ausführen mit Validierung von Parametern
  **und** Rückgabe, strukturierter Fehler `{ok:false,error:{code,message,pointer}}`).
- Schema-Subset-Regel als Test: nur `type, properties, required, additionalProperties(false), enum, minimum, maximum,
  items, anyOf, $ref, $defs, description, default`; jedes Objekt mit `additionalProperties:false`.
- Tool-Name = ID mit `_` statt `.`; Rückabbildung über Map; Kollision oder ungültiger Name (`^[a-zA-Z0-9_-]{1,128}$`) → Fehler.
- Export: Funktion erzeugt `tools.json` (Name, Beschreibung, Schema) und `docs/commands.md` (Deutsch, Tabelle je Namespace);
  CLI-Anbindung folgt in M1-07 – hier eine Test-Hilfe, die vergleicht, ob die eingecheckten Dateien aktuell sind.
- In M1-02 registrierte Commands nur zum Test (`app.version` readOnly). Ausführung auf dem Message-Thread (Assert).
- **Mini-Spike in der Karte:** Fehlertexte von pboettch für 5 Fälle (falscher Typ, fehlendes Pflichtfeld, Zusatzfeld,
  enum, Bereich) im Bericht zeigen – sie gehen später an Claude.
