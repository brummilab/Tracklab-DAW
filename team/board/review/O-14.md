# O-14: `tracklab-cli io` – Audio-Geräte-Befehle für Handtest V1

Meilenstein: M1 · Agent: test-writer → implementer · Herkunft: Abschluss M1-07 (10.10.2026) · Abhängig: M1-06, M1-07

## Fakten
- Handtest V1 (`docs/testing/manual/M1.md`) braucht `io.list_device_types`, `io.list_devices`, `io.get_device`,
  `io.set_device` von Hand, mit echter Hardware (ALSA/JACK, WASAPI/ASIO).
- `run-commands` braucht ein Projekt und erlaubt nur undoable/readOnly-Commands → `io.set_device` gesperrt.
- PO-Wunsch (RESUME): nach M1-07 selbst testen können.

## Auftrag
1. Unterbefehl `tracklab-cli io <command-id> [params-json]`: führt genau einen `io.*`-Command der Registry aus (kein
   zweiter Codepfad), ohne Projekt, mit echtem Gerätemanager; nur Commands mit Präfix `io.` erlaubt, sonst Exit 2.
   Ausgabe eine JSON-Zeile, Exit 0/1/2 wie die übrigen Unterbefehle.
2. Option für einen eigenen Einstellungsordner (`--settings-dir`), damit der Handtest die echten Einstellungen nicht
   überschreibt; ohne Option der normale Benutzerordner.
3. `docs/testing/manual/M1.md`: `<Aufruf>` durch den echten Aufruf ersetzen (Linux und Windows, kopierbar).
4. Tests mit Fake-Gerätetyp wie in `tests/io/` (keine echte Hardware im Gate).

## Lead-Entscheidungen nach Test-Writer (10.10.2026)
1. Unbekannte `io.*`-ID → Exit 1, `unknown_command` (wie `run-commands`); Nicht-`io.`-ID → Exit 2, `usage`.
2. Ungültiges/Nicht-Objekt-JSON → Exit 2, Code `usage` (Aufruffehler), nichts ausgeführt; Schemaverletzung → Exit 1,
   `invalid_params` mit Pointer.
3. Ausgabe `{"ok":true,"result":{…}}`; `docs/testing/manual/M1.md` verweist auf `result.…`.
4. Persistenz in-process (zwei `runCli`-Aufrufe) genügt; ohne `--settings-dir` wird nicht getestet.
5. `M1.md`: `<Aufruf>` durch echte, kopierbare Aufrufe ersetzen (Linux Bash, Windows PowerShell inkl. JSON-Quoting),
   `--settings-dir` im Abschnitt „Vor dem Test“ statt Sicherungskopie empfehlen.
